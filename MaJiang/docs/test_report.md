# 上海麻将：300 局实战测试报告（2026-11-07）

## 结论

最终版在真实界面上连打 300 局：没有脚本错误，没有卡死，局末画面和裁判的牌全部一致。

| 项目 | 最终结果 |
|---|---|
| 脚本错误 / 卡死 / 画面与裁判不一致 | 0 / 0 / 0 |
| 平均帧率 | 71.7 fps（测试机刷新率约 75 Hz） |
| 超过 33 ms 的帧 | 0.97% |
| 主线程长任务 | 每局 0.1 次，最长 383 ms |
| 内存 | 不持续增长，在 2～6 MB 之间起伏 |
| 对旧版实力 | 每局净赢 +0.208 ± 0.062 点（z=3.3） |

没有在真手机上测过。手机尺寸和慢 CPU 都是模拟的，触屏手感、发热和手机 GPU 的表现还需要实机确认。

## 怎么测的

- **真实界面连打**：无头 Edge 跑真实页面和真实 GPU（Intel UHD 770），844×390、2 倍像素，模拟手机横屏，10 倍速，3 个页面同时跑。
- **监控内容**：脚本错误、卡死、每局结束时画面和裁判是否一致、帧间隔、长任务、内存（每 15 局回收后读一次）、牌是否出屏 / 互相盖住 / 被界面挡住。
- **其他条件**：1600×900 和 667×375 各跑一轮；再用正常速度加 4 倍 CPU 降速跑 3 局，模拟慢手机。
- **不开界面的对局**：同牌对打 10000 副牌（共 40032 局），另逐局查失误 300 局。

## 发现并修好的问题

| 问题 | 测到的情况 | 处理后 |
|---|---|---|
| 结算框太高，「下一局」按钮可能出屏 | 13 局按钮出屏，56 局内容溢出 | 内容区可滚动，按钮一直可见；844×390 下 300 局里 1 局需要滚动，3 px |
| 玩家的花牌被手牌盖住 | 258 次采样 | 花牌移到右侧两列，不再发生 |
| 你当庄起手 14 张时，最左边的牌出屏 | 1600×900 下 6 px，667×375 下 3 px | 手牌已满时不留摸牌空位，复测 0 |
| 名牌挡住对家和左右家的牌 | 多种屏幕都有 | 名牌移位，16:9 小屏再上移；复测 0 |
| 声音节点内存泄漏：音频未解锁时节点排队，永远释放不掉 | 内存只涨不跌 | 未解锁时不排队 |
| 向听缓存上限太大 | 2000 局涨到 24.57 MB，还在涨 | 上限从 30 万条降到 2 万条，约 7 MB 封顶，每局只慢 0.5 ms |
| 电脑杠牌后手牌已经胡不了（杠成死牌） | 查失误时发现 | 杠的奖励只在还能胡时才算，复查 0 次 |

## 实战效果

最终版四家同时对局（10008 局）：

- 胡牌局 79.1%，流局 20.9%。自摸 2253 次，放炮 5750 次，拉杠胡 6 次，七捉一 6 次。
- 平均每胡 8.0 点，最高 80 点。
- 牌型：混一色 5083、开宝 1504、碰碰胡 1385、清一色 1203、门清 255、混碰 242、大吊车 205、乱风向 76、杠开 60、清碰 20、海底捞月 20。
- 各座位胡牌 2024 / 2012 / 2035 / 1944，卡方 2.5（p≈0.47），座位之间没有显著差异。

逐局查失误（300 局）：

| 检查项 | 结果 |
|---|---|
| 吃碰成死牌 | 0 次 |
| 放过点炮 | 0 次 |
| 能听却拆听（或听死张） | 60 / 1742 次（3.4%），其中放弃 ≥4 张好听的 15 次；大多是在追清一色、门清或乱风向 |
| 冒险打牌（自己没听，打三副清一色对手那门的生张） | 580 次，修改前 872 次 |

## 用测试数据改进 AI

| 改动 | 结果 | 处理 |
|---|---|---|
| 防守权重加到 2 倍 / 3.5 倍 | -0.155 / -0.226 点（3.5 倍 z=-2.5） | 否决 |

| 再调一轮参数（40 轮） | 接受 0 次 | 已到平台期，不再调 |

统计出的几个数字：对手亮了三副同一门时，后期打那门的牌放炮率 6.45%；对手亮了四副时放炮率约 9%；外面一张不剩的牌也不算安全，因为顺子听牌不需要别人手里有这张。

## 还剩下的小问题

- **对家的花牌偶尔被压住**：对家四副副露且其中有杠时，杠上那张会盖住后排的花牌。300 局里 2579 次采样有 14 次，最多 3 张。名牌上有花数，不影响判断。
- **结算框偶尔要滚动**：667×375 下 36 局里有 1 局，多出 61 px，按钮仍然可见。

## 这些数字的局限

- 实力只和自己的旧版比过，没有和真人或其他麻将程序比过。
- 帧率来自桌面 Intel 核显，不代表手机 GPU。CPU 降速模拟不了手机发热降频。
- 上面的流畅度表是修最后两处布局之前跑的。之后的改动只有手牌空位的计算和名牌的 CSS，复测见下。

# 第二轮：900 局、真人操作测试和设计审查（2026-11-07）

## 结论

最终版在三种屏幕上电脑代打 300 局、模拟真人操作 120 局：脚本错误、卡死、画面与裁判不一致全部是 0。另外修好了一个只有手机上才会碰到的严重问题（切后台回来牌桌变黑），以及几处规则说明和界面问题。AI 这一轮的 8 项实验没有一项赢过现行版本，AI 保持不变。

## 怎么测的

- **900 局**：三个页面分别用 844×390（手机横屏）、667×375（小手机）、1600×900（电脑），各打 300 局。同时在跑 AI 对打，所以这一轮的帧率不作数，只看错误、卡死、一致性、内存和布局。
- **真人操作**（新工具 `tests/robot.mjs`）：不再由电脑代打你的座位，而是用真实的鼠标和触摸事件打牌：一半时间照 AI 的决定点，一半随便点；故意打「刚吃的牌」；吃碰杠胡过都点；同时乱点牌桌、连点、开关规则和记录面板、切速度和声音、改窗口大小、转成竖屏再转回、冻结页面模拟切后台、让 WebGL 上下文丢失再恢复。
- **设计审查**：另请一个 AI 审查员只读检查规则、公平、界面竞态、手机和 AI 设计。它的每条意见都先核实：规则对照上海麻将资料，界面问题实测，AI 建议对打。

## 900 局的结果

| | 结果 |
|---|---|
| 局数 | 900（三种屏幕各 300） |
| 错误 / 卡死 / 不一致 | 0 / 0 / 0 |
| 出屏 / 被界面挡住 | 0 / 0 |
| 牌互相盖住 | 只有「对家的杠压住花牌」，9183 次采样里 30 次 |
| 内存 | 每个页面连打 300 局，在 1.8～6.4 MB 之间起伏，回收后回落，没有持续增长 |
| 越打越慢 | 没有：每个页面头 50 局和最后 50 局每局用时一样（16.2 / 16.5 秒等） |

## 发现并修好的问题

| 问题 | 怎么发现的 | 处理 |
|---|---|---|
| 手机切到别的应用再回来，系统可能收回显存（WebGL 上下文丢失），之后牌桌一直是黑的，只能刷新，牌局也没了 | 读代码发现，电脑代打的测试碰不到 | 收到丢失通知后暂停绘制，恢复时重建所有显存资源，牌局照常继续。机器人测试丢失 17 次，每次都恢复出画面 |
| 手机上对家名牌带「三口」标记时变宽，压住右家副露的牌面 | 真人操作测试 | 手机上名牌左移。现在偶尔压住对家一张牌背（667×375 下最多），牌背不含信息 |
| 放弃碰某张牌后，同一圈里还能明杠这张，和「不能再碰」的规则不一致 | 审查 | 明杠也禁止，规则说明同步 |
| 裁判或电脑出错时整局卡住，只能刷新 | 审查 | 弹出「这一局出错了」，可以直接开始下一局；已强行制造错误验证 |
| 规则说明写「荒番：上一局流局 ×2」，程序实际按上海的荒番数计算（流局 +1、有人胡 -1） | 审查 | 程序符合百度经验上的上海打法，改的是说明 |
| 同时和两家绑定三口时怎么付，说明里没写 | 审查 | 说明补上：两家各付 5 份；其中一家放炮付 2 份、另一家付 1 份 |

## 审查意见中没有采纳的

- **花数表**（审查员怀疑碰和暗刻应该不同、中发白不该多 1 花）：维基百科、百度经验和网上的上海麻将规则三处资料都和程序一致，不改。
- **三口自摸付 5 份、互相绑定**（审查员说没听过）：同样三处资料一致，不改。
- **拉杠胡时被抢那家「少一张牌」**：那张牌被胡牌的人拿走了，画面上飞到了胡牌的人那里，不是错误。
- **AI 建议**：「加杠时考虑被拉杠」（+0.003 ± 0.005 点，测不出）、「打给三口绑定者按 2 份算」（-0.068，z=-2.2）、「绑定后做牌价值放大」（-0.063，z=-2.0），都没有赢过现行版本。详见 `selfplay_log.md`。
