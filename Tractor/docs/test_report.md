# 拖拉机 80 分：300 局实战测试报告（2026-11-07）

## 结论

最终版在真实界面上连打 300 局：没有脚本错误，没有卡死，局末画面和裁判的牌全部一致。电脑思考基本不再卡动画，实力也比测试前有提高。

| 项目 | 最终结果 |
|---|---|
| 脚本错误 / 卡死 / 画面与裁判不一致 | 0 / 0 / 0 |
| 平均帧率 | 72.6 fps（测试机刷新率约 75 Hz） |
| 超过 33 ms 的帧 | 0.56% |
| 主线程长任务 | 300 局共 12 次，最长 393 ms |
| 内存 | 平稳，约 2.5～2.8 MB |
| 对测试前的版本（v3） | 闲家多拿 +2.09 ± 0.93 分（z=2.2） |
| 对纯启发式版本（v2） | 闲家多拿 +11.84 ± 1.11 分（z=10.6） |

没有在真手机上测过。手机尺寸和慢 CPU 都是模拟的，触屏手感、发热和手机 GPU 的表现还需要实机确认。

## 怎么测的

- **真实界面连打**：无头 Edge 跑真实页面和真实 GPU（Intel UHD 770），844×390、2 倍像素，模拟手机横屏，10 倍速，3 个页面同时跑。
- **监控内容**：脚本错误、卡死、每局结束时画面和裁判是否一致、帧间隔、长任务、内存（每 15 局回收后读一次）、牌是否出屏 / 互相盖住 / 被界面挡住。
- **其他条件**：1600×900 和 667×375 各跑一轮；再用正常速度加 4 倍 CPU 降速跑 3 局，模拟慢手机。
- **不开界面的对局**：同牌对打（对 v3 300 副牌、对 v2 200 副牌），另逐局查失误 300 局。

## 发现并修好的问题

| 问题 | 测到的情况 | 处理后 |
|---|---|---|
| 电脑思考时卡动画：抽样推演一口气算完 | 正常 CPU 下每局 34 次长任务；4 倍降速下每局 52.3 次，最长 773 ms，超过 250 ms 的帧 121 个 | 推演切成小段，每 8 ms 让出一帧；4 倍降速下每局 0.5 次，最长 346 ms，超过 250 ms 的帧只有 1 个 |
| 声音节点内存泄漏：音频未解锁时节点排队，永远释放不掉 | 内存只涨不跌 | 未解锁时不排队，内存平稳 |
| 名牌挡住左右两家的牌背 | 667×375 下 272 次采样 | 手牌和名牌都挪了位置，16:9 小屏再上移；复测 0 |

## 实战效果

- 通关 9 次，无主 26 局，抠底 118 局。

# 第二轮：900 局、真人操作测试和设计审查（2026-11-07）

## 结论

最终版在三种屏幕上电脑代打 300 局、模拟真人操作 121 局：脚本错误、卡死、画面与裁判不一致全部是 0。修好了一个只有手机上才会碰到的严重问题（切后台回来牌桌变黑）、一个规则 bug（从 K 跳过 A 直接通关），以及几处亮主和选牌的界面问题。AI 这一轮的实验没有一项赢过现行版本，AI 保持不变。

## 怎么测的

- **900 局**：三个页面分别用 844×390（手机横屏）、667×375（小手机）、1600×900（电脑），各打 300 局。同时在跑 AI 对打，所以这一轮的帧率不作数，只看错误、卡死、一致性、内存和布局。
- **真人操作**（新工具 `tests/robot.mjs`）：不再由电脑代打你的座位，而是用真实的鼠标和触摸事件打牌：一半时间用「提示」出牌，一半手动选牌，包括单张、对子、故意甩牌、选错张数再清空；埋牌时手点 8 张、多选一张再取消、按住滑动连选；发牌途中和最后都会亮主。同时乱点牌桌、连点、开关面板、切速度和声音、改窗口大小、转竖屏、冻结页面模拟切后台、让 WebGL 上下文丢失再恢复。
- **设计审查**：另请一个 AI 审查员只读检查规则、公平、界面竞态、手机和 AI 设计。它的每条意见都先核实：规则对照资料，界面问题实测，AI 建议对打。

## 900 局的结果

| | 结果 |
|---|---|
| 局数 | 900（三种屏幕各 300） |
| 错误 / 卡死 / 不一致 | 0 / 0 / 0 |
| 出屏 / 互相盖住 / 被界面挡住 | 0 / 0 / 0（20858 次采样） |
| 内存 | 每个页面连打 300 局，稳定在 2.5～2.9 MB |
| 通关 | 32 次，之后都正确地从 2 重新开始 |

这一轮后半段每局变慢（20 秒到 26 秒），是因为中途开始同时跑 AI 对打、抢了 CPU；最终验证时没有别的任务，头 30 局和最后 30 局每局用时一样。

## 发现并修好的问题

| 问题 | 怎么发现的 | 处理 |
|---|---|---|
| 手机切到别的应用再回来，系统可能收回显存（WebGL 上下文丢失），之后牌桌一直是黑的，只能刷新 | 读代码发现，电脑代打的测试碰不到 | 收到丢失通知后暂停绘制，恢复时重建所有显存资源，牌局照常继续。机器人测试丢失 18 次，每次都恢复出画面 |
| 庄家在 K 守住、升 2 级时直接「通关」，没打 A；闲家同样情况却要打 A。和规则说明「守住 A 才算通关」矛盾 | 审查，实测确认 | 升级最多到 A，打 A 并守住才算通关；新增测试 |
| 闲家被罚成负分时，结算页「赢墩得分」算错（只赢 5 分却显示 10） | 审查 | 赢墩得分单独累计；新增测试 |
| 发牌途中你点了亮主，拿到下一张牌的电脑却先被问，能抢在你前面亮 | 审查 | 你的亮主先生效；万一被抢先，会提示「亮主慢了一步」 |
| 亮主按钮每发一张牌就重建一次，手指按下到抬起之间按钮换了，点击会丢；别人亮了更大的主后，你失效的按钮一直留着 | 审查 | 按钮没变就不重建；没有可亮的主时收起按钮 |
| 当庄 33 张牌时，手机上每张牌只露出 17～20 像素，一张张点容易点错 | 真人操作测试量出来 | 按住滑动可以连选或连续取消；提示和 README 写明 |
| 按住滑动时在画布外松手，之后鼠标经过牌还在继续选 | 审查 | 按下时捕获指针，在哪里松手都算结束 |
| 电脑亮主的牌立刻盖回去，你只能看记录回忆 | 审查 | 名牌上显示「亮 ♠2」，直到这张牌打出去 |
| 裁判或电脑出错时整局卡住，只能刷新 | 审查 | 弹出「这一局出错了」，可以直接开始下一局；已强行制造错误验证 |

## 审查意见中没有采纳的

- **抠底三连对 ×16**（审查员说是通行打法）：Pagat 和 Robert Ying 的规则都是 ×12（最大一组张数 ×2），维基百科两种都列了。没找到上海专门的说法，保持 ×12。
- **甩牌失败不罚分**（审查员说是上海传统）：Pagat 写的是罚分，另两处不罚；没有找到上海的依据，保持罚 10 分，规则说明里已写清。
- **AI 建议**：亮主改得挑剔（-0.72 / +0.17 / -1.16 分）、最后一墩按底牌估值（0.00：最后一墩每家只能把剩下的牌全出完，这个值从来不影响决定），都没有赢过现行版本。另外自己试的 6 项也没有通过。详见 `selfplay_log.md`。
